0. pkg/httproute.go:662: The BackendTLSPolicy resolution block (sort policies, match targetRef, record conflict status, load the transport, record Accepted/NoValidCACertificate, return a RefNotPermitted condition) is copied almost line for line in httproute.go loadHTTPServers, grpcroute.go loadGRPCServers (line 373) and tlsroute.go loadTLSServers (line 361). The new backend client certificate feature had to add the same `serversTransport.Certificates = listener.BackendClientCertificates` line to all three copies (httproute.go:759, grpcroute.go:470, tlsroute.go:458), so each later feature will again need three edits. Fix: Pull out one helper, for example `p.resolveBackendTLSPolicy(gatewayName, gatewayNamespace string, listener gatewayListener, namespace string, backendName gatev1.ObjectName, svcPort corev1.ServicePort, route metav1.Object, statusReport) (*gatev1.BackendTLSPolicy, *metav1.Condition)`. It returns the winning policy after recording all PolicyAncestorStatus entries. Each caller then only builds its own HTTP or TCP transport from that policy and attaches listener.BackendClientCertificates.
1. pkg/tlsroute.go:483: loadTCPServersTransport duplicates loadServersTransport (httproute.go:790): the same SAN mapping, WellKnownCACertificates shortcut, CACertificateRef kind and group checks, ConfigMap/Secret lookup and the same ResolvedRefs conditions. The only difference is the output struct (dynamic.TLSClientConfig nested in TCPServersTransport, or fields on ServersTransport). Fix: Add a shared `p.resolveBackendTLSValidation(namespace, policy) (serverName string, insecureSkipVerify bool, sans []tls.SAN, rootCAs []types.FileOrContent, metav1.Condition)`. Keep loadServersTransport and loadTCPServersTransport as thin adapters that copy these values into their own struct.
2. pkg/kubernetes.go:488: The backend client certificate belongs to the Gateway, but it is copied into every gatewayListener (BackendClientCertificates, line 184) by a separate loop after the listeners are loaded. Its matching condition is stored on gatewayWithListeners instead. One Gateway-level fact is therefore kept in two places, and any listener built somewhere else silently gets no certificate. Fix: Store the certificates next to the condition on gatewayWithListeners, either as a struct `backendClientCertificate struct{ certs tls.Certificates; condition *metav1.Condition }` or as two fields. Carry them through gatewayListenersForParentRef, since matchingGatewayListenersForParentRef already knows the Gateway. Pass them to the route loaders from there and remove the per-listener field and the copy loop.
3. pkg/kubernetes.go:1198: makeGatewayStatus now takes gwl.gateway, gwl.listeners and gwl.backendClientCertificateCondition as three separate arguments that all come from the same gatewayWithListeners value. Every new Gateway-level input makes the parameter list longer. Fix: Change the signature to `makeGatewayStatus(gwl gatewayWithListeners, addresses []gatev1.GatewayStatusAddress, accepted bool)` and update the call at line 530 and Test_makeGatewayStatus to build a gatewayWithListeners.
4. pkg/client.go:843: withoutForeignConditions and mergeGatewayStatus (line 860) each repeat the ownership predicates `slices.Contains(gatewayConditionTypes, t)` and `slices.Contains(listenerConditionTypes, t)` (lines 846, 851, 863, 877). That gives four copies of the ownership rule that this change extended with ResolvedRefs. Fix: Add `func isOwnedGatewayCondition(c metav1.Condition) bool` and `func isOwnedListenerCondition(c metav1.Condition) bool`. Use them in both functions, for example `slices.DeleteFunc(conds, not(isOwnedGatewayCondition))` and `if !isOwnedGatewayCondition(c)`.
5. pkg/httproute.go:29: loadHTTPRoute and loadGRPCRoute (grpcroute.go:23) are the same ~100-line loop over parentRefs and listeners: Accepted and ResolvedRefs bookkeeping, hostname conflict check, AttachedRoutes++, servedRules registration and the status record. They differ only in the route kind, the configuration loader and the Record*Status call, so any change to attachment rules has to be made twice. Fix: Extract a generic `p.attachHTTPLikeRoute(ctx, gateways, route metav1.Object, kind string, parentRefs []gatev1.ParentReference, hostnames []gatev1.Hostname, load func(match gatewayListenersForParentRef, listener gatewayListener, hostnames []gatev1.Hostname) ([]httpRouteRouter, metav1.Condition), record func(gatev1.RouteParentStatus), conf, attached, served)`. Merge the identical httpRouteRouter and grpcRouteRouter types into one type.
6. pkg/grpcroute.go:475: The scheme is hard-coded as the literal "https", here and in httproute.go:767, even though the package defines schemeHTTPS and the protocol helpers use it. Fix: Replace `protocol := "https"` with `protocol := schemeHTTPS` in both files.
