0. pkg/function_call_expr.go:1: The new files `function_call_expr.go` and `tuple_cons_expr.go` (and their tests) do not use the `ast_` prefix. The parse functions are also split inconsistently: `parseFunctionCallExpr` and `parseTupleConsExpr` live next to their types, but `parseObjectConsExpr` and `parseObjectConsKeyExpr` stay in `parser.go`. Fix: Rename the files to `ast_function_call_expr.go`, `ast_function_call_expr_test.go`, `ast_tuple_cons_expr.go` and `ast_tuple_cons_expr_test.go`. Pick one place for parse functions. Either move `parseFunctionCallExpr` and `parseTupleConsExpr` into `parser.go` next to `parseObjectConsExpr`, or move `parseObjectConsExpr` and `parseObjectConsKeyExpr` into `ast_object_cons_expr.go`.
1. pkg/tuple_cons_expr.go:34: `parseTupleConsExpr` and `parseFunctionCallExpr` (`function_call_expr.go:59`) have the same body. Each loops over native sub-expressions, partitions the tokens, appends the tokens before each sub-expression, parses it with `parseExpression`, adds the node to a `nodeSet`, appends the leftover tokens and wraps the result in an `Expression`. Fix: Extract a helper such as `parseSubExpressions(children *nodes, set nodeSet, natives []hclsyntax.Expression, from inputTokens)` that appends the parts and the trailing tokens. Each parser then becomes: create the node, call the helper, then `wrapExpr.wrap(...)`.
2. pkg/function_call_expr.go:20: `FunctionCallExpr.args` (and `TupleConsExpr.elems` in `tuple_cons_expr.go:15`) is filled during parsing but nothing reads it. `Variables` walks `children` instead, and no accessor exposes it. The field is write-only state that has to be kept in sync for nothing. Fix: Add public accessors that read the sets, matching `ObjectConsExpr.Items`: `func (call *FunctionCallExpr) Args() []*Expression` and `func (t *TupleConsExpr) Exprs() []*Expression`, each built from `nodeSet.List()`. If no accessors are wanted yet, remove the fields and the `Add` calls.
3. pkg/ast_expression.go:214: `AsObjectConsExpr`, `AsFunctionCallExpr`, `AsTupleConsExpr` and `asQuoted` are four copies of the same nil-check and type assertion on `e.wrapped.content`. This change added two of them. `AsObjectConsExpr` also has no doc comment, while the new methods do. Fix: Add a generic helper, `func wrappedAs[T nodeContent](e *Expression) T { var zero T; if e.wrapped == nil { return zero }; t, _ := e.wrapped.content.(T); return t }`, and make each `As*` method a one-line call to it. Add a doc comment to `AsObjectConsExpr` that matches the other two.
4. pkg/parser.go:494: `parseTemplateExpr` sets `expr.wrapped = expr.children.Append(quoted)` directly. It skips `Expression.wrap`, which every other wrapping parser now uses and which guards against wrapping twice. Fix: Replace those lines with `expr.wrap(quoted)`.
5. pkg/parser.go:432: `parseObjectConsExpr` reads `before.writerTokens`, `open.writerTokens` and `from.writerTokens` directly. The rest of the parser, including the new `parseFunctionCallExpr` and `parseTupleConsExpr`, uses the `inputTokens.Tokens()` accessor. It also uses `children` and `expr.children` for the same list in the same function. Fix: Use `.Tokens()` everywhere in `parseObjectConsExpr`, and use the `children` local throughout (`node := children.Append(item)`).
6. pkg/ast_object_cons_expr.go:222: `splitAtLineEnd` is a method on `*ObjectConsExpr` but never uses its receiver. It is a pure token helper, and it repeats the rule that a line comment ending in '\n' ends the line, which `partitionLineEndTokens` in `parser.go` already encodes. Fix: Make it a package-level function, `splitAtLineEnd(toks Tokens) (Tokens, Tokens, bool)`, and update the three call sites. Put the shared check, whether a token ends a line (`TokenNewline`, or `TokenComment` whose bytes end in '\n'), in one small helper. Use that helper from both `splitAtLineEnd` and `partitionLineEndTokens`.
7. pkg/ast_object_cons_expr.go:128: `appendItem` builds newline and comma `Token` literals inline, and `ObjectConsItem.init` builds the '=' token inline as well. Fix: Build them once with small helpers next to `newIdentToken` in `tokens.go`, for example `newNewlineToken()`, `newCommaToken()` and `newEqualToken(spacesBefore int)`, and use those helpers here.
8. pkg/ast_expression_test.go:116: `TestExpressionVariablesFunctionCallTupleCons` repeats the whole loop body of `TestExpressionVariablesObjectCons`.
