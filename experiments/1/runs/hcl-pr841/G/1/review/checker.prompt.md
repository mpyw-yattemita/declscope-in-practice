0. pkg/ast_expression.go:145: Variables checks each wrapped type in its own branch (AsObjectConsExpr, AsFunctionCallExpr, AsTupleConsExpr). Every new composite expression type will need another branch here, even though all three types already have a `variables()` method. Fix: Declare an unexported interface `interface{ variables() []*Traversal }` and write `if v, ok := e.wrapped.content.(variablesLister); ok { ret = append(ret, v.variables()...) }` once, in place of the three type-specific branches.
1. pkg/ast_expression.go:211: AsObjectConsExpr, AsFunctionCallExpr, AsTupleConsExpr and asQuoted repeat the same nil check and type assertion on e.wrapped. Fix: Add a generic helper `func wrappedAs[T nodeContent](e *Expression) T` that returns the zero value when e.wrapped is nil or holds another type. Make the four methods one-line calls to it.
2. pkg/tuple_cons_expr.go:25: TupleConsExpr.variables is identical to FunctionCallExpr.variables (function_call_expr.go:42). Both loop over a nodeSet of *Expression and join their Variables(). Fix: Add `func variablesOf(exprs nodeSet) []*Traversal` in ast_expression.go and have both methods return `variablesOf(tuple.elems)` and `variablesOf(call.args)`.
3. pkg/tuple_cons_expr.go:42: parseTupleConsExpr and parseFunctionCallExpr (function_call_expr.go:61) duplicate the same loop: partition each native sub-expression, append the tokens before it, parse it, add it to a nodeSet, append the leftover tokens, then wrap the result in an Expression. Both also build their struct inline, unlike newObjectConsExpr and the other constructors in the package. Fix: Add newTupleConsExpr() and newFunctionCallExpr() constructors. Extract `parseExpressionList(natives []hclsyntax.Expression, from inputTokens, children *nodes) nodeSet` (or one that returns the wrapping node) and call it from both parse functions.
4. pkg/parser.go:496: parseTemplateExpr sets `expr.wrapped = expr.children.Append(quoted)` directly. That skips the new Expression.wrap helper, which every other wrapping parser uses and which guards against double wrapping. Fix: Replace the line with `expr.wrap(quoted)`.
5. pkg/ast_object_cons_expr.go:119: variables uses a `, ok` type assertion that can never fail, because items only ever holds *ObjectConsItem nodes. It also reaches into item.key.content and item.value.content directly instead of using the KeyExpr and ValueExpr accessors defined in the same file. Fix: Loop over o.Items(). Use `key := item.KeyExpr()` and `item.ValueExpr().Expr()`, and remove the `ok`/`continue` branch.
6. pkg/ast_object_cons_expr.go:268: isLineEnd, hasComma and newlineToken are methods on ObjectConsExpr but never use the receiver. isLineEnd also repeats the 'comment ends in \n' check that already exists in parser.go:728 (partitionLineEndTokens) and format.go:438. Fix: Turn the three methods into package-level functions, for example in tokens.go. Add one `tokenEndsLine(tok *Token) bool` helper and use it in appendItem, partitionLineEndTokens and format.go.
7. pkg/ast_object_cons_expr.go:142: appendItem is about 120 lines long and does four separate jobs: detecting whether the object is multi-line, splitting the tokens into gaps, rebuilding the children, and building the new key and separator. It also calls n.BuildTokens(nil) twice per item inside the gap loop. Fix: Extract `isMultiline(itemNodes) bool`, `splitGaps(stream, itemNodes) (gaps []Tokens, tail Tokens)` and `newObjectConsKey(key string, multiline bool) *ObjectConsKeyExpr`. In the gap loop, compute `toks := n.BuildTokens(nil)` once and reuse it.
8. pkg/node.go:128: nodes.Clear clears the holders but leaves each node's list, before and after links set. appendItem (ast_object_cons_expr.go:193-196) works around this by detaching every item before calling Clear, so the item nodes can be appended again. Fix: Make Clear unlink every node: walk the list, save `next := n.after`, then set n.list, n.before and n.after to nil and call setContentHolder(nil). Then remove the Detach loop in appendItem.
9. pkg/node.go:302: inTree.parent is never assigned anywhere in the package, so the parent check in the new inTree.assertUnattached can never fire. The only check that works is the one on holder. Fix: Remove the parent field and the parent branch of assertUnattached. Keep only the holder check.
10. pkg/function_call_expr.go:41: Several new doc comments end with a stray empty `//` line: function_call_expr.go:41 and :60, tuple_cons_expr.go:24 and :41, ast_object_cons_expr.go:118, parser.go:74 (inputTokens) and parser.go:383 (parseExpression). Fix: Delete the trailing `//` line from each of these comment blocks.
11. pkg/parser.go:451: In the changed parseObjectConsExpr, the loop variable `node := expr.children.Append(item)` shadows the `node` type. The function also reads `.writerTokens` directly, while the rest of parser.go and the new parse functions call `.Tokens()`. Fix: Rename the variable, for example `expr.items.Add(expr.children.Append(item))`, and replace each `x.writerTokens` with `x.Tokens()`.
12. pkg/ast_expression_test.go:150: checkASTExpressionVariables compares slices with a hand-written length check and element loop. TestObjectConsExprItems (ast_object_cons_expr_test.go:89) compares them by joining strings. The package already uses go-cmp in its tests. Fix: Use `if diff := cmp.Diff(test.want, got); diff != "" { t.Fatalf(...) }` in both places.
