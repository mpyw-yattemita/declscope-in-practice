0. pkg/grpcroute.go:201: httproute.go now carries the per-listener context (gatewayName, gatewayNamespace, listener, route, statusReport) in httpRouteLoader. The GRPCRoute path (loadGRPCRouteConfiguration, loadGRPCService, loadGRPCBackendRef, loadGRPCServers) was extended the other way: the same 4-5 values are passed as positional parameters through every level. So the two route kinds that share loadHTTPAndGRPCRoutes now use two different patterns. Fix: Add a grpcRouteLoader struct that mirrors httpRouteLoader. Build it in loadGRPCRoute and turn loadGRPCRouteConfiguration/loadGRPCService/loadGRPCBackendRef/loadGRPCServers into its methods, removing the gatewayName/gatewayNamespace/listener/statusReport parameters.
1. pkg/tlsroute.go:213: loadTLSWRRService, loadTLSService and loadTLSServers (and loadTLSRoute at line ~150) also pass gatewayName, gatewayNamespace, listener and statusReport positionally. The only reason is to forward them to loadBackendTLS. Fix: Add a tlsRouteLoader struct, like httpRouteLoader and the proposed grpcRouteLoader, that holds gatewayName, gatewayNamespace, listener, route and statusReport. Make the TLSRoute loaders its methods.
2. pkg/backendtlspolicy.go:21: loadBackendTLS takes 8 parameters. gatewayName, gatewayNamespace and listener are only used for two things: building the PolicyAncestorStatus ref (name, namespace, listener.SectionName) and reading listener.BackendClientCertificate. The package already has listenerRef (GatewayNamespace, GatewayName, SectionName), which is exactly this ancestor identity. Fix: Change the signature to loadBackendTLS(ancestor listenerRef, clientCert *tls.Certificate, routeGeneration int64, namespace string, serviceName gatev1.ObjectName, svcPort corev1.ServicePort, statusReport *statusReport). Build AncestorRef from ancestor, and update the three callers (loadHTTPServers, loadGRPCServers, loadTLSServers).
3. pkg/backendtlspolicy.go:45: The inner targetRef loop does not stop after the first targetRef of a policy that matches the service and port. If a policy lists the same Service twice (for example two sectionNames, or one with and one without a sectionName), the second match finds tlsConfig != nil. It then records the policy as Conflicted with itself, overwriting its Accepted ancestor status. The loop also checks only Name and repeats the group/kind filter that ListBackendTLSPoliciesForService already does. Fix: Extract a helper policyTargetsPort(policy, serviceName, svcPort) bool that checks targetRefs. Loop over policies only (one decision per policy), so a policy cannot conflict with itself.
4. pkg/client.go:430: ListBackendTLSPoliciesForService appends the policy once for each matching targetRef. A policy that targets the same Service several times (different sectionNames) is returned several times. loadBackendTLS then processes it as several policies and reports a false conflict. Fix: Add `break` after `servicePolicies = append(servicePolicies, policy)` (or use slices.ContainsFunc over TargetRefs), so each policy is returned once.
5. pkg/backendtlspolicy.go:139: loadBackendTLSPolicyClientConfig builds the full metav1.Condition literal for BackendTLSPolicy ResolvedRefs 7 times, changing only status, reason and message. gatewaytls.go added makeGatewayResolvedRefsCondition for the same need on Gateways, so the new code uses two styles. Fix: Add makeBackendTLSPolicyResolvedRefsCondition(generation int64, status metav1.ConditionStatus, reason gatev1.BackendTLSPolicyReason, message string) metav1.Condition, modeled on makeGatewayResolvedRefsCondition. Use it for every return in loadBackendTLSPolicyClientConfig and for the conflict condition in loadBackendTLS.
6. pkg/gatewaytls.go:45: resolveCACertificateRefs and loadBackendTLSPolicyClientConfig (backendtlspolicy.go:200-236) both read a CA bundle from a ConfigMap's "ca.crt" key and handle 'not found' and 'empty ca.crt' in the same way. resolveCACertificateRefs also repeats the ListenerConditionResolvedRefs literal 5 times. Fix: Extract p.getCACertificate(kind, namespace, name string) (string, error), which reads ca.crt from a ConfigMap or Secret, and call it from both functions. Add makeListenerResolvedRefsCondition(generation, reason, message) for the five listener condition returns.
7. pkg/kubernetes.go:631: loadGatewayListeners resolves the Gateway-level frontend validation (Default and PerPort) on every call. That means once for the Gateway and again for each ListenerSet attached to it, and every call repeats the ConfigMap lookup and ReferenceGrant check. resolveBackendClientCertificate, the other new Gateway-level TLS setting, is resolved once in loadConfigurationFromGateways. Fix: In loadConfigurationFromGateways, resolve the Default and PerPort frontend validations once per Gateway, next to resolveBackendClientCertificate, for example in a gatewayTLS struct. Pass the result into loadGatewayListeners and loadListenerSetListeners instead of resolving inside them.
8. pkg/kubernetes.go:490: The backend client certificate is a Gateway-level value, but it is copied into every gatewayListener (BackendClientCertificate). The resolution error is stored separately on gatewayWithListeners. One fact is split across two structs, and the copy loop is required for correctness. Fix: Store the certificate as backendClientCertificate on gatewayWithListeners, next to backendClientCertificateErr. Add it to gatewayListenersForParentRef in matchingGatewayListenersForParentRef, so route loaders read it from the match. Then remove gatewayListener.BackendClientCertificate and the copy loop.
9. pkg/kubernetes.go:1102: makeGatewayStatus now takes gateway, listeners and backendClientCertificateErr as three parameters. All three are fields of the gatewayWithListeners value the caller already holds (gwl). Fix: Change the signature to makeGatewayStatus(gwl gatewayWithListeners, addresses []gatev1.GatewayStatusAddress, accepted bool) and call it as p.makeGatewayStatus(gwl, addresses, accepted).
10. pkg/client.go:505: UpdateGatewayStatus compares withoutForeignConditions(current) with the desired status, then writes mergeGatewayStatus(current, desired). Two new helpers encode the same ownership rule from opposite sides. Route and policy status updates instead merge first and compare the merged result with the current one. Fix: Compute merged := mergeGatewayStatus(currentGateway.Status, status) and return early if gatewayStatusEqual(currentGateway.Status, merged). Then delete withoutForeignConditions and its test, and keep a single isOwnedCondition helper (slices.Contains over gatewayConditionTypes/listenerConditionTypes) in mergeGatewayStatus.
11. pkg/grpcroute.go:368: loadGRPCServers and loadHTTPServers (httproute.go:650) both call loadBackendTLS and newServersTransport, then use the same 'protocol := "https" unless no transport, else derive it from the port' block with the same comment. Only the protocol function changes. Fix: Extract a helper serviceScheme(backendTLS *dynamic.TLSClientConfig, svcPort corev1.ServicePort, fallback func(corev1.ServicePort) (string, error)) (string, error) that returns schemeHTTPS when backendTLS != nil. Use schemeHTTPS instead of the "https" literal.
12. pkg/tlsroute.go:364: The passthrough test `listener.TLS != nil && listener.TLS.Mode != nil && *listener.TLS.Mode == gatev1.TLSModePassthrough` appears at tlsroute.go:162 and :364, and in slightly different forms in tcproute.go:149 and kubernetes.go:753.
