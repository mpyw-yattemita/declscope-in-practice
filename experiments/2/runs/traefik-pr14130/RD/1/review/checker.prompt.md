This directory holds one Go package, `pkg/`. A reviewer listed the findings
below. Check each one against the code.

0. pkg/client.go:430: ListBackendTLSPoliciesForService appends a policy once for every matching targetRef. A policy that targets the same Service twice (for example two sectionNames) is returned twice. loadBackendTLSPolicyClientConfig then handles the second copy as a different policy, so it records a Conflicted status against itself. The targetRef matching is also split: group and kind are checked here, name and sectionName in backendtlspolicy.go. Fix: Append each policy at most once (`break` after the first matching ref, or use slices.ContainsFunc). Move the full targetRef check (group, kind, name, sectionName) into one helper, e.g. `backendTLSPolicyTargetsPort(ref, serviceName, svcPort)`, and use it in both files.
1. pkg/backendtlspolicy.go:46: The inner loop over policy.Spec.TargetRefs runs the build and status logic once per matching targetRef. A policy with both a sectionName-less ref and a sectionName ref for the same port is built twice and marks itself Conflicted. Fix: Pick the matching targetRef with slices.ContainsFunc and the shared helper. Then process each policy once in the outer loop, with no nested per-ref build and status code.
2. pkg/backendtlspolicy.go:93: loadBackendTLSPolicyClientConfig and buildBackendTLSPolicyClientConfig build about ten nearly identical metav1.Condition literals. Only Type, Status, Reason and Message change, and ObservedGeneration and LastTransitionTime are repeated each time. This hides the real decision logic (conflict, accepted, invalid). Fix: Add small constructors such as `policyCondition(policy, condType, status, reason, msg)` and `routeResolvedRefsFalse(generation, reason, msg)`, and use them for every literal in the file.
3. pkg/backendtlspolicy.go:215: The ca.crt lookup from a ConfigMap or Secret (get the object, read ca.crt, error if empty) duplicates the ConfigMap ca.crt lookup in resolveCACertificateRefs (kubernetes.go:1177). The two copies already produce different error messages. Fix: Extract `p.getCACertificate(namespace string, kind gatev1.Kind, name gatev1.ObjectName) (string, error)` that supports ConfigMap and Secret. Call it from buildBackendTLSPolicyClientConfig and resolveCACertificateRefs, and wrap the error in each caller's condition.
4. pkg/backendtlspolicy.go:22: loadBackendTLSPolicyClientConfig takes 8 parameters. gatewayName, gatewayNamespace, listener and statusReport are passed unchanged through loadGRPCService → loadGRPCBackendRef → loadGRPCServers and through the TLSRoute chain (loadTLSWRRService → loadTLSService → loadTLSServers) only to reach this function. httproute.go already solves this with httpRouteLoader. Fix: Group the four values in a struct, e.g. `backendTLSContext{gatewayName, gatewayNamespace string; listener gatewayListener; statusReport *statusReport}`, or make the method take a gatewayListenersForParentRef match. Pass that struct instead, and reuse it in httpRouteLoader and in the GRPC and TLS loaders.
5. pkg/httproute.go:524: The scheme is chosen by checking `serversTransport != nil` as a proxy for 'a BackendTLSPolicy applies'. This forces loadBackend (line 480) to add ForwardingTimeouts only after loadServers returns, and it needs a comment to explain that ordering. grpcroute.go:368 has the same coupling. Fix: Branch on `clientConfig != nil` (the BackendTLSPolicy result) instead of serversTransport. Then remove the ordering comment at line 480, since timeouts can be added in any order.
6. pkg/grpcroute.go:347: loadGRPCServers is a near copy of httpRouteLoader.loadServers (httproute.go:500): get backend addresses, load BackendTLSPolicy, choose the scheme, build the server URLs. The only differences are the protocol function and the 'GRPCBackendRef' or 'HTTPBackendRef' text in messages. Fix: Extract one `p.loadHTTPServers(ctx backendTLSContext, namespace string, ref gatev1.BackendObjectReference, generation int64, protocolOf func(corev1.ServicePort) (string, error), refLabel string)`. Have both routes call it with getGRPCServiceProtocol or getHTTPServiceProtocol.
7. pkg/httproute.go:443: loadBackend calls loadHTTPBackendRef with the raw backend.ref, and loadHTTPBackendRef dereferences *backendRef.Group and *backendRef.Kind (line 697). resolveBackend has already computed the defaulted group and kind, but they are thrown away. A nil Group or Kind (now also reachable from RequestMirror filters through loadRequestMirror) panics. Fix: Change the signature to loadHTTPBackendRef(namespace, group string, kind gatev1.Kind, name gatev1.ObjectName), pass backend.group, backend.kind and backend.ref.Name, and remove the pointer dereferences.
8. pkg/tlsroute.go:375: `serversTransport != nil && serversTransport.TLS != nil` is a roundabout `clientConfig != nil`. The passthrough expression is written twice (lines 162 and 369). In passthrough mode a TLS ServersTransport is still created and attached even though it is never used. Fix: Add `isTLSPassthrough(listener gatewayListener) bool` and use it at lines 162 and 369. Set `TLS: clientConfig != nil && !passthrough`, and only build the TCPServersTransport when the servers actually dial TLS.
9. pkg/client.go:893: policyAncestorStatusesEqual and routeParentStatusesEqual (line 923) contain the same unordered, two-way ContainsFunc comparison. Only the element type and the equality function differ. Fix: Add a generic `unorderedEqualFunc[T any](a, b []T, eq func(T, T) bool) bool` and write both functions as one-line calls to it.
10. pkg/backendtlspolicy.go:21: Doc comments end with a stray empty `//` line: here, at backendtlspolicy.go:140 and at gatewaybackendtls.go:14. Fix: Delete the trailing `//` line in the three comments.
