0. pkg/ast_expression.go:244: variableNodes asks for each wrapped kind in turn (AsObjectConsExpr, AsFunctionCallExpr, AsTupleConsExpr). Every new composite expression type needs another branch here, and a missed branch silently drops its variables from Variables and RenameVariablePrefix. Fix: Add an unexported interface `variableNodeser { variableNodes() []*node }`, which ObjectConsExpr, FunctionCallExpr and TupleConsExpr already satisfy. Reduce the method to `nodes := e.absTraversals.List(); if v, ok := e.wrapped.content.(variableNodeser); e.wrapped != nil && ok { nodes = append(nodes, v.variableNodes()...) }`.
1. pkg/ast_expression.go:200: AsObjectConsExpr, AsFunctionCallExpr, AsTupleConsExpr and asQuoted (line 258) are four copies of the same nil-check plus type assertion on e.wrapped. Fix: Add one generic helper, `func wrappedAs[T nodeContent](e *Expression) T { var zero T; if e.wrapped == nil { return zero }; v, _ := e.wrapped.content.(T); return v }`, and make each As* method a one-line call to it. Also add a doc comment to AsObjectConsExpr, which is the only As* method without one.
2. pkg/ast_tuple_cons_expr.go:28: TupleConsExpr.variableNodes is a line-for-line copy of FunctionCallExpr.variableNodes (ast_function_call_expr.go:58). Both loop over a nodeSet of *Expression and concatenate their variableNodes. Fix: Add `func exprSetVariableNodes(set nodeSet) []*node` in ast_expression.go and make both methods `return exprSetVariableNodes(x.elems / call.args)`.
3. pkg/parser.go:531: parseTupleConsExpr is a copy of parseFunctionCallExpr (line 499). Each partitions the sub-expressions by range, appends the tokens between them, wraps the result and sets the parent of every child expression. Only the native slice (Args or Exprs) and the target nodeSet differ. Fix: Extract `parseExprList(native []hclsyntax.Expression, from inputTokens, children *nodes, set nodeSet)`, which does the loop and the trailing tokens. Add a shared `wrapExpression(c nodeContent, set nodeSet) *node` that wraps the content and calls setParent on each member. Both functions then become a few lines each.
4. pkg/parser.go:561: parseTemplateExpr assigns `expr.wrapped = expr.children.Append(quoted)` directly. The other wrapping parsers go through the new Expression.wrap helper, so this path skips wrap's already-wrapped check, and wrapped expressions are built two different ways. Fix: Replace it with `expr.wrap(quoted)`.
5. pkg/ast_attribute.go:26: Parent tracking for assertUnattached is set only in the parser (parser.go:290, 461, 517, 549) and in ObjectConsItem.setValueExpr. Attribute.init asserts but never calls setParent, and Body.SetAttributeRaw/Value/Traversal (ast_body.go:218, 239, 260) swap expressions with ReplaceWith but neither set the new parent nor clear the old one. So an expression returned by Attribute.Expr after SetAttributeValue passes SetItem's assertUnattached, which contradicts SetItem's doc comment, and a replaced attribute expression keeps a stale parent. Fix: Add `Attribute.setExpr(expr *Expression)`, modeled on ObjectConsItem.setValueExpr: clear the old expression's parent, append or ReplaceWith, then `expr.setParent(a.expr)`. Call it from init and from the three Body.SetAttribute* methods. In parseAttribute, use it instead of the separate setParent call.
6. pkg/ast_object_cons_expr.go:224: tokenEndsLine and splitClosing (line 206) are methods on *ObjectConsExpr but never use the receiver. The rule that a comment ending in a newline also ends the line is implemented again in partitionLineEndTokens (parser.go:796). Fix: Make them package-level functions (`tokenEndsLine(tok *Token) bool`, `splitClosing(tokens Tokens)`) and update the call sites in appendItem and isMultiline. Put the comment-ends-with-newline test in one small helper that both tokenEndsLine and partitionLineEndTokens use.
7. pkg/ast_object_cons_expr.go:123: ObjectConsExpr.variableNodes reaches into private node contents (`item.key.content.(*ObjectConsKeyExpr)`, `key.wrapped.content.(*Expression)`, `value.expr.content.(*Expression)`) even though accessors for these already exist. Fix: Give ObjectConsKeyExpr its own `variableNodes()`, which returns nil when literalName and otherwise the wrapped expression's nodes. Write the loop as `for _, item := range o.Items() { ret = append(ret, item.KeyExpr().variableNodes()...); ret = append(ret, item.ValueExpr().Expr().variableNodes()...) }`.
8. pkg/ast_function_call_expr.go:31: Name walks every child with walkChildNodes and uses a `done` flag only to emulate an early break. Alternatively, record the name tokens' node in a `name *node` field in parseFunctionCallExpr and build the name from that.
9. pkg/ast_expression.go:243: Several new doc comments end with an empty `//` line just before the declaration: here, ast_function_call_expr.go:57, ast_tuple_cons_expr.go:27, ast_object_cons_expr.go:122, node.go:283, parser.go:498 and parser.go:530.
