0. pkg/ast_object_cons_expr.go:206: isLineEnd does the same job as tokenIsNewline in format.go (format.go:431): a newline token, or a single-line comment that ends in '\n'. The 'a comment ends in a newline' rule is also written a third time in partitionLineEndTokens in parser.go. These copies can drift apart. Fix: Delete isLineEnd and call tokenIsNewline in hasLineEnd and appendItem. Move tokenIsNewline, hasLineEnd and newNewlineToken into tokens.go next to newIdentToken, because they are general token helpers and are not specific to objects.
1. pkg/parser.go:545: parseTemplateExpr sets expr.wrapped = expr.children.Append(...) directly, and so does newObjectConsKeyExprForName (ast_object_cons_expr.go:276). Expression.wrap was added for exactly this and has a guard against double wrapping, but these two places skip it. Fix: Replace both with expr.wrap(quoted) / expr.wrap(newQuoted(...)), so wrap is the only place that sets Expression.wrapped.
2. pkg/ast_expression.go:221: AsObjectConsExpr, AsFunctionCallExpr, AsTupleConsExpr and asQuoted repeat the same 'if wrapped is nil, return nil; type-assert the content' code four times. AsObjectConsExpr also has no doc comment, while the new methods next to it do. Fix: Add a generic helper `func wrappedAs[T nodeContent](e *Expression) T` (it returns the zero value when e.wrapped is nil or the assertion fails). Make each As* method a one-line call to it. Add a doc comment to AsObjectConsExpr in the same style as the others.
3. pkg/ast_expression.go:145: Variables type-switches by hand on each composite expression kind and calls its variables(). Each new wrapped kind needs one more if-block here, and a kind that is left out silently loses its traversals from Variables and from RenameVariablePrefix. Fix: Define an internal interface `type variablesNode interface{ variables() []*Traversal }`. In Variables, do one check: `if v, ok := e.wrapped.content.(variablesNode); ok { ret = append(ret, v.variables()...) }` (only when e.wrapped is not nil).
4. pkg/parser.go:533: Expression.parent is set by hand in several unrelated places: parseAttribute (parser.go:290), parseObjectConsExpr (parser.go:459), parseExprList (here) and SetItem (ast_object_cons_expr.go:84, 90). Object key expressions never get a parent. Because of this, assertUnattached in SetItem gives inconsistent protection, and every new container has to remember the rule. Fix: Add a single helper, for example `func appendExpr(children *nodes, expr *Expression) *node`. It calls expr.assertUnattached(), appends expr, sets expr.parent to the owning node and returns the node. Use it in the parser for attributes, object keys and values, and list elements, and in SetItem. Add the matching detach step (clear parent) in one place too.
5. pkg/parser.go:519: parseExprList takes content, children and set as three separate arguments. children and set are really fields of content, so a caller can pass a mismatched combination. The function also builds the wrapping Expression, which is a separate job from parsing the list. Fix: Change the signature to `parseExprList(children *nodes, set nodeSet, nativeExprs, from)` and have it fill in only the list. Let parseFunctionCallExpr and parseTupleConsExpr do the wrapping themselves with newExpression().wrap(expr), as parseObjectConsExpr already does. Better still, have it set the parent through the attach helper from the previous finding.
6. pkg/ast_object_cons_expr.go:312: ObjectConsExpr.variables sits after the ObjectConsKeyExpr methods, away from the other ObjectConsExpr methods. It reaches into raw nodes (o.items.List(), item.key.content.(*ObjectConsKeyExpr), key.wrapped.content.(*Expression), item.value.content.(*ObjectConsValue)) even though accessors for all of these exist. Fix: Move it next to Items/ItemFor and write it with the accessors: `for _, item := range o.Items() { if k := item.KeyExpr(); !k.literal { ret = append(ret, k.expr().Variables()...) }; ret = append(ret, item.ValueExpr().Expr().Variables()...) }`. Add a small `func (k *ObjectConsKeyExpr) expr() *Expression` accessor and use it in name() as well.
