below. Check each one against the code.

0. pkg/ast_object_cons_expr.go:117: The appendItem doc comment says the layout is "described in appendItemTokens", but there is no function called appendItemTokens. The layout rules are in splitObjectTail. Fix: Change the comment to "laid out as described in splitObjectTail".
1. pkg/ast_object_cons_expr.go:315: newObjectConsKeyExprFor sets `expr.wrapped = expr.children.Append(...)` directly. This skips Expression.wrap, the helper that guards against wrapping twice. parser.go:553 (parseTemplateExpr) does the same, while the new parseObjectConsExpr, parseFunctionCallExpr and parseTupleConsExpr all call wrap(). Fix: Use `expr.wrap(newQuoted(...))` here, and `expr.wrap(quoted)` in parseTemplateExpr, so every wrapped Expression is built the same way.
2. pkg/ast_expression.go:214: AsObjectConsExpr, the new AsFunctionCallExpr and AsTupleConsExpr, and asQuoted repeat the same nil check and type assertion. Each new wrapped expression kind adds another copy. Fix: Add a generic helper, `func wrappedAs[T nodeContent](e *Expression) T`, that returns the zero value when `e.wrapped == nil` or the type does not match. Make each As* method a one-line call to it.
3. pkg/ast_expression.go:155: Variables finds nested traversals by asserting against an anonymous `interface{ variables() []*Traversal }`. ObjectConsExpr, FunctionCallExpr, TupleConsExpr and ObjectConsKeyExpr all depend on this unnamed contract, so a misspelled or mistyped method on a new expression kind is silently skipped. Fix: Declare a named interface, `type variablesNode interface{ variables() []*Traversal }`, in ast_expression.go. Use it in the assertion, and add compile-time checks such as `var _ variablesNode = (*FunctionCallExpr)(nil)` for each implementer.
4. pkg/ast_function_call_expr.go:44: expressionsVariables is a shared helper used by both FunctionCallExpr and TupleConsExpr, but it lives in the function-call file. Readers of ast_tuple_cons_expr.go have to look in an unrelated file to find it. Fix: Move expressionsVariables to ast_expression.go, next to Expression.Variables, which it complements.
5. pkg/ast_object_cons_expr.go:234: newNewlineToken is added in the object file, but the same `{TokenNewline, '\n'}` literal is still written out inline in ast_attribute.go:42, ast_block.go:48/60 and ast_body.go:305. The `{TokenEqual, '='}` literal is also repeated in ast_attribute.go:34 and ast_object_cons_expr.go:269, and splitObjectTail builds a comma token inline. Fix: Move newNewlineToken to tokens.go, next to newIdentToken, and add newEqualToken and newCommaToken there. Replace the inline literals in Attribute.init, ObjectConsItem.init, splitObjectTail, Block.init and Body.AppendNewline with these helpers.
6. pkg/ast_object_cons_expr.go:266: ObjectConsItem.init has the same shape as Attribute.init, but only Attribute.init calls `expr.assertUnattached()`. The item version depends on its one caller, SetItem, to check. The two init functions no longer follow the same contract. Fix: Move the `expr.assertUnattached()` call from SetItem into ObjectConsItem.init, as Attribute.init does. Keep a check in SetItem only for the replace path, before `ReplaceWith`.
7. pkg/ast_body.go:212: ObjectConsExpr now has SetItem(key, expr), with SetItemRaw/Value/Traversal as one-line wrappers. Body.SetAttributeRaw/Value/Traversal still each repeat the same find-or-replace-or-append block. The two parallel APIs are built differently, and the Body copies have no unattached check on the replace path. Fix: Add an internal `func (b *Body) setAttribute(name string, expr *Expression) *Attribute` that mirrors ObjectConsExpr.SetItem, including the `expr.assertUnattached()` check. Rewrite the three SetAttribute* methods as one-line calls to it.
8. pkg/node.go:93: There are now two different "is attached" checks. node.assertUnattached checks `n.list` and is used by Body.appendItem at ast_body.go:34. The new inTree.assertUnattached checks the `attached` flag kept up to date by setAttached. They can disagree, and readers cannot tell which one is authoritative. Fix: Switch Body.appendItem to the inTree check, e.g. `c.(interface{ assertUnattached() })` on the content, or a shared helper. Then delete node.assertUnattached so that attachment state is tracked only by inTree.attached.
9. pkg/node.go:136: nodes.Append, nodes.Insert and nodes.AppendUnstructuredTokens set `n.list = ns` again after calling AppendNode/InsertNode, which already set it and now also call setAttached. Append also builds the node with a literal instead of newNode. Fix: Remove the redundant `n.list = ns` lines from Append, Insert and AppendUnstructuredTokens, and use `newNode(c)` in Append and Insert.
10. pkg/ast_object_cons_expr.go:350: ObjectConsKeyExpr.variables checks `k.wrapped == nil`, but newObjectConsKeyExpr is the only constructor and always sets wrapped to a non-nil *Expression node. The check suggests a state that cannot happen. Fix: Remove the nil check and return `k.wrapped.content.(*Expression).Variables()`.
11. pkg/ast_object_cons_expr_test.go:16: TestObjectConsExprVariables and TestFunctionCallAndTupleConsVariables (ast_function_call_expr_test.go:79) have the same test structure and the same loop body: check against hclsyntax, collect variables, rename, compare.
