0. pkg/grpcroute.go:23: loadGRPCRoute is a near line-for-line copy of loadHTTPRoute (httproute.go:29). Both have the same parentRef/listener acceptance loop, attachedRoutes conflict check, ResolvedRefs aggregation, servedRules registration and status building. The only differences are the route kind, the config loader called and the status recorder called. loadTLSRoutes (tlsroute.go:24) repeats most of this loop again. Fix: Extract one helper, e.g. `p.attachRoute(ctx, routeObj metav1.Object, kind string, parentRefs, hostnames, gateways, attachedRoutes, servedRules, load func(listener gatewayListener, hostnames []gatev1.Hostname) ([]routeRouter, metav1.Condition), merge func(*dynamic.Configuration)) []gatev1.RouteParentStatus`. It returns the parent statuses. loadHTTPRoute and loadGRPCRoute then reduce to calling it and recording the statuses, and TLS reuses it with attachedRoutes set to nil.
1. pkg/grpcroute.go:120: httpRouteRouter (httproute.go:126), grpcRouteRouter and tlsRouteRouter (tlsroute.go:134) are identical structs `{Name string; Conf *dynamic.Configuration}`. Fix: Replace the three with one type, `routeRouter`, defined next to servedRules in kubernetes.go, and use it in all three loaders.
2. pkg/httproute.go:600: loadHTTPServers, loadGRPCServers (grpcroute.go:373) and loadTLSServers (tlsroute.go:361) each repeat about 100 lines of the same BackendTLSPolicy logic: listing, sorting, targetRef/sectionName filtering, building the ancestor status, the conflict conditions, the Accepted/ResolvedRefs conditions and recordBackendTLSPolicyStatus. Only the transport type differs. The copies have already drifted: the HTTP copy has the typo 'wen wrong'. Fix: Extract `p.resolveBackendTLSPolicy(gatewayName, gatewayNamespace, namespace string, backendRef gatev1.BackendObjectReference, svcPort corev1.ServicePort, listener gatewayListener, routeGeneration int64, statusReport *statusReport) (*gatev1.BackendTLSPolicy, *metav1.Condition)`. It returns the single winning policy, or a route ResolvedRefs error condition, and records all ancestor statuses. Each caller then only converts the winning policy into its own HTTP or TCP servers transport.
3. pkg/tlsroute.go:479: loadTCPServersTransport duplicates loadServersTransport (httproute.go:724) almost exactly: SAN mapping, the WellKnownCACertificates check, ConfigMap/Secret CA lookup and all the conditions. Fix: Extract `p.resolveBackendTLSValidation(namespace string, policy *gatev1.BackendTLSPolicy) (serverName string, insecureSkipVerify bool, sans []tls.SAN, rootCAs []types.FileOrContent, cond metav1.Condition)`, or have it fill a `dynamic.TLSClientConfig`. 4. pkg/tlsroute.go:120: The deny-unknown-host router and service are written inside the `for _, route := range routes` loop, so they are rewritten on every route. The decision only depends on the final conf.TCP.Routers. Fix: Move the `if len(conf.TCP.Routers) > 0 { ... }` block after the route loop.
5. pkg/httproute.go:354: loadService builds a new mirrorServiceLoader with the same arguments that loadHTTPRouteConfiguration (line 142) already used to build one. Because loadService is itself called through that loader, the closure is rebuilt on every backend and every mirror. Fix: Pass the loader created in loadHTTPRouteConfiguration down through loadWRRService to loadService as a `mirrorServiceLoader` parameter, and delete the newMirrorServiceLoader call in loadService.
6. pkg/httproute.go:204: The retry middleware is appended under `if err == nil && retry != nil` before the `switch` that handles `err != nil`. The same error is tested twice, and the order of the steps is hard to follow. Fix: Move the retry append into the `default:` and internal-service branches of the switch, or return early on err, so that err is tested once.
